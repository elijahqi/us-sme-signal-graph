# External validation and pilot protocol

The project seeks independent correction, reproduction, and evaluation. A GitHub issue, star, or download is not counted as adoption by itself.

## Independent reproduction

A reproduction should identify the commit or release, operating environment, commands used, expected and observed hashes or counts, deviations, and any code or data changes. A reproduction is counted only after the evidence is public or privately retained with the contributor's consent.

## Data correction

A correction should identify a candidate ID, the disputed field, an original public evidence URL, and the requested action. Do not post personal contact data, private records, credentials, or access-controlled content.

## Pilot interest

A pilot begins only after the participant and maintainer agree in writing on:

- organization and authorized contact;
- concrete use case and decision being supported;
- version and candidate set used;
- success and failure measures;
- permitted public attribution;
- confidentiality, data-rights, and correction boundaries;
- start and end dates.

The project will not backfill a pilot start date, create fictional users, count an introductory call as adoption, or publish a testimonial without approval.

## Minimum evaluation measures

Depending on the use case, a pilot report should record verified candidates, false positives, previously unknown suppliers, analyst time, decision changes, missing sectors, and corrections. National economic impact should not be inferred from candidate discovery alone.
