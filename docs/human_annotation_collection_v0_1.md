# Local human annotation interface v0.1

The user requested an interactive version of the human-material preview and local saving on 2026-09-20 UTC. This implementation begins collection of human core judgments; deploying it does not establish a human gold standard or satisfy the original validation gates.

The interface uses the original 300 double-review IDs from the frozen 1,200-row sample, preserving their evidence excerpts, capability/state tasks, source URLs and page fingerprints. It does not select cases using model labels or oversample the 795-case boundary stratum. No model outputs, rankings, query intent or machine-predicted scale are read into the interface. Reviewers enter their own pseudonymous alias and declare independent review. Each browser session can retrieve only its own reviewer's answers; a second reviewer uses a separate browser profile or private window and another alias. The system does not certify reviewer identity or independence merely from this declaration.

All decisions start blank. Clickable fields capture the five components, final yes/no/unclear judgment, primary exclusion reason, source status, confidence and conflicts. Reviewers supply the enterprise name when identity is resolved, a brief rationale and review minutes. Positive final decisions additionally require production state and capability/location quotations. A reviewer can select an unchanged source-text span and explicitly copy it into a quote field; the app does not propose an answer. Supplemental sources and their viewing times must be recorded separately. This preserves the original guide's allowance for supplemental evidence; a comparison restricted to frozen excerpts must identify cases using added sources.

Input validation checks completeness and enum membership. Contradictory positive/component judgments are retained with a flag, not silently corrected. The interface requires an exclusion reason for nonpositives and `none` for positives. Supplementary scale, legal-form, web-visibility, affiliate and SBA fields can be added later; their absence is explicitly recorded. Thus “completed” in the interface means the core form was submitted, not that every field or gate of protocol v0.3 has been completed. The original 1,200 first-human-annotation plan, at least 300 independent second annotations, adjudication, agreement assessment and 200-pair entity audit remain separate requirements.

Edits are automatically saved as drafts; submitting a complete core form advances to the next record. Refresh restores saved values. A timer measures visible-page time and can be paused or corrected; external-source review time must be added manually. Timer values are not independently verified measurements of active human work.

All data stays in the ignored local `human_annotations_v0_1` directory. Each reviewer has separate current records and an append-only revision history, with timestamps and source/collection fingerprints. Stale revisions are rejected rather than overwriting a newer tab's changes. The app binds only to 127.0.0.1, checks request origin and a page nonce, and uses a browser session cookie. Exports contain only the active reviewer's records. No remote hosting, email, model calls or automatic publication is performed by this app.

Validation used fictional records in a separate temporary store. Tests covered durable save/restart, reviewer isolation, revision preservation, incomplete submissions and origin protection. Browser checks exercised clicking, completion, refresh restoration and automatic draft saving. Test annotations are not part of the research store.
